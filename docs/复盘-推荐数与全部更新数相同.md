# 复盘：「推荐精读」与「全部更新」数量相同（信息大量丢失）

- **发现时间**：2026-10-22
- **发现方式**：用户观察日报界面，发现两个 tab 徽章都显示 21，质疑「为什么推荐和全部更新一样」
- **结论**：不是抓取故障，是**默认配置过保守 + 界面主动丢弃无正文条目**，属于设计决策失误（推翻了 2026-10-16 的 commit `09aa943`）

---

## 一、现象

2026-10-22 日报（`公众号日报-精读版-2026-10-22-0838.html`）：

| 位置 | 显示值 |
|------|--------|
| 顶部「今日更新」 | 106 |
| tab「⭐ 推荐精读」 | 21 |
| tab「📚 全部更新」 | **21** ← 异常 |

同时，正文抓取日志显示 `成功 21 篇（失败 4）`，即 106 篇里只有 21 篇有正文，其余 85 篇在界面上**完全不可见**。

---

## 二、根因（三个因素叠加）

### 1. 默认只抓推荐前 25 篇正文

`scripts/run_daily.sh` 第 20 行：

```bash
FULL="${FULL:-25}"
```

第 129-130 行：`FULL != 0` 时执行 `weread_content.py --top 25`。

**后果**：全量清单（`articles-weread-*.json`，106 篇）里，只有推荐 Top25 被送去抓正文，其余 81 篇**从未有过正文数据**。

### 2. 全部视图主动跳过无正文条目

`scripts/wx_reader.py` 原代码：

```python
has = bool(fv.get("content_html"))
if not has:
    continue   # 未取到正文: 不进清单(展示也读不了, 无意义)
```

**后果**：106 篇里 85 篇无正文（含上面那 81 篇从未抓过的）→ 全部被 `continue` 掉 → 列表只剩 21 篇。
**这 21 篇恰好等于推荐数**，于是两个 tab 数字相同。

> 注：这个 `continue` 是 2026-10-16 commit `09aa943`「无正文文章不进全部清单（展示也读不了）」引入的。
> 当时的判断在当时的数据下成立，但随着默认配置只抓 Top25，它变成了大规模信息丢弃。

### 3. tab 徽章用错了变量

```python
f'<button id="tabAll" ...>📚 全部更新<span class="n">{n_full}</span></button>'
```

`n_full` = 有正文的篇数，`n_total` = 全量篇数。徽章应显示 `n_total`。
顶部「今日更新」用的是 `n_total`，所以显示 106 是正确的 —— 只有 tab 徽章这一处取错变量。

---

## 三、无法抓取文字正文的篇目：真相

对 4 篇失败篇目用 Playwright 逐一实测（非推测）：

| 篇目 | 接口返回特征 | 判定 |
|------|-------------|------|
| AIGCRank《全球AI办公卷到哪一步了？》 | `PAGE_MID=mmbizwap:pages/common_share.html` | **图片型文章**，正文即图片 |
| 赛博禅心《阶跃这手机，质感相当不错！》 | 同上（分享模板） | 图片型文章 |
| 智能体AI《Ontology 到底怎么落地？》 | 同上（分享模板） | 图片型文章 |
| 腾讯技术工程《AI是什么？？？？？？》 | 有 `id="js_content"`，但内容全为 `<svg>` | **纯 SVG 交互排版** |

### 已验证无解的三条路

| 尝试 | 结果 |
|------|------|
| 重试同一接口 3 次 | 稳定返回分享模板，无效 |
| 换 5 个接口端点（`/web/mp/detail`、`/article`、`/review` 等） | 全部 404，只有 `/web/mp/content` 有效 |
| 直连 mp 原文链接（og:url） | 触发「环境异常」人机验证 |

**结论**：这类文章在纯文本层面客观取不到正文，`weread_content.py` 原先的判定没错。真正的错误是**界面把它们整个丢掉了**。

---

## 四、修复内容（3 个文件）

### `scripts/run_daily.sh` —— 根治

```bash
FULL="${FULL:-0}"    # 原为 25
```

第 125-131 行：`FULL=0` 走 `weread_content.py --all --reuse`，每天抓**全部更新**的正文。
`--reuse` 保证已抓过的正文不重复下载，增量抓取仅需十几秒。

### `scripts/weread_content.py` —— 榨取残值

抓不到正文时，不再只记一条 `failed`，而是新建 `unreadable` 数组落盘可用信息：

```python
unreadable.append({
    "key": ..., "account": ..., "title": ...,
    "real_url": m["real_url"] or a.get("url", ""),   # 原文链接（og:url）
    "digest": a.get("digest") or m["desc"],          # 摘要
    "cover": a.get("cover", ""),                     # 封面图
    "page_mid": page_mid,                            # 模板类型
    "reason": "图片型分享页" | "SVG交互排版",           # 失败原因分类
    "text_len": ...,
})
```

同时 `--reuse` 会复用历史 `unreadable` 记录，避免每天重复抓已知不可读的文章。

### `scripts/wx_reader.py` —— 恢复信息 + 修正计数

1. **tabAll 徽章**改用 `n_total`
2. **全部视图不再跳过无正文条目**，改为渲染「摘要 + 缩略图 + 原文链接」卡片
3. 新增 `_pick_thumb()` 规范化 mmbiz 缩略图 URL
4. 计数提示改为「共 106 篇（94 篇含全文可精读 · 12 篇为图片/交互型，仅标题与摘要）」
5. 新增 CSS：`.alist .nbody/.thumb/.ndigest/.ntag/.nlink`

## 六、经验教训

1. **「展示也读不了，所以不展示」是危险的设计原则。** 读不了正文的条目，仍然携带标题、摘要、封面、原文链接 —— 这些信息本身就是价值。正确做法是**降级展示**，不是隐藏。
2. **默认配置决定成败。** `FULL=25` 这个默认值让「全部更新」名不副实。凡默认值与功能命名冲突时，应以命名语义为准（「全部」就该是真全部）。
3. **数量对不上是强信号。** 两个语义不同的 tab 显示同一个数字，必然有信息丢失。这类异常应作为自检项。
4. **诊断要区分「抓取故障」与「源侧无此数据」。** 本次 4 篇的失败是后者，若不实测就盲目加重试/换代理，是浪费。

# 公众号精读日报 · 云端部署工作流（灵光云主机版）

> 部署形态：整套能力跑在灵光的云主机上，**用户的电脑完全不参与**。用户只需要做三件事：①把代码交给灵光 ②扫一次码 ③每天收日报。
> 本文档分两部分：第一部分是你（用户）要做的；第二部分是给灵光的部署 Prompt，整段复制即可。

---

## 第一部分：部署前你只需要做一件事

**把项目代码交给灵光**。两条通道任选：

- **通道 1（已就绪，推荐）：GitHub 私有仓库** → **https://github.com/xiaohuye/wechat-daily**（私有，2026-10-28 已建好并推送，40 个文件，已排查无任何登录态/凭证/个人数据）。把仓库地址告诉灵光即可。灵光需要你先在它的授权管理里给这个仓库开访问权限（它是私有仓库），或者你把仓库临时转为公开后告诉灵光地址。
- **通道 2：直接发送**。把 `scripts/` 和 `config/` 两个文件夹打包发给灵光，让它放到云主机同一个目录下。

其余一切（装环境、登录、试跑、挂定时）都由灵光在云主机上自己完成，见第二部分。

## 第二部分：给灵光的部署 Prompt（整段复制粘贴）

```
请在你自己的云主机上为我部署一套「公众号精读日报」系统，之后每天自动运行，
全程不要使用我的电脑。代码在这个私有仓库：https://github.com/xiaohuye/wechat-daily
（如果克隆时提示无权限，告诉我，我去授权后你再试）。
请严格按以下阶段执行，每个阶段完成后向我汇报结果再进入下一阶段；任何一步
做不到就停下来告诉我原因，不要跳过、不要用替代方案假装完成。

【阶段 0：环境自检】
1. 检查云主机上有没有 python3 和 pip；没有就先装。
2. 检查能不能长期保存一个数据目录（部署后重启/隔天仍在）。这一点很重要：
   微信读书的登录凭证必须跨天保留，否则我每天都要扫码。如果你的云主机
   每次任务都是全新环境、文件会丢，现在就告诉我，我们先讨论持久化方案。
3. 检查内存：无头浏览器 + 抓取峰值约需 1GB。不够就告诉我。

【阶段 1：获取代码并安装依赖】
1. 把代码仓库克隆到云主机（或把我发的文件夹放到 ~/wechat-daily）。
2. 安装依赖：
   pip install playwright requests
   playwright install chromium
   playwright install-deps        # Linux 系统库，缺了浏览器起不来
3. 向我汇报：python 版本、chromium 是否安装成功。

【阶段 2：登录微信读书（只需一次）】
1. 运行：python3 scripts/weread_login.py --timeout 900
2. 它会生成二维码图片：output/weread_qr.png
3. 把这张二维码图片发到我们的对话里，我用手机微信扫。
4. 每 25 秒刷新一次二维码截图并重发，直到我扫完（脚本会写入
   data/weread_login_status.txt = LOGIN_OK）。
5. 扫码成功后告诉我。以后登录态失效（报 errCode=-2010）才需要重复这个流程。

【阶段 3：冒烟试跑（只抓 1 个公众号）】
1. 运行：python3 scripts/weread_fetch.py --days 1 --limit 1
2. 成功标准：退出码 0，data/ 下生成 articles-*.json，说「共 N 篇，失败 0」。
3. 如果报「未找到 Chromium」或浏览器崩溃，检查 playwright install-deps 是否装全，
   重装后重试一次；再失败就把报错原文发我。

【阶段 4：全链路试跑（生成第一份日报）】
1. 运行：SKIP_IMA_SYNC=1 DAYS=1 TOP=30 FULL=25 bash scripts/run_daily.sh
   （约 4-6 分钟；会依次完成 抓取→排序→分析→抓正文→生成日报）
2. 成功标准：退出码 0，output/ 下出现「公众号日报-精读版-<时间戳>.html」。
3. 日报是单文件网页（约 1MB，正文已内嵌）。请用你能做到的方式把它交给我：
   a) 直接把 HTML 文件发到对话里；或
   b) 在云主机上起一个只读 HTTP 服务托管 output/ 目录，把链接发我；
   选一条可行的，告诉我你用了哪种。
4. 同时把 data/ranked-*.json 里排名前 10 的文章读出来，在对话里汇报：
   标题 + 公众号 + 一句话推荐理由。

【阶段 5：挂每日定时任务】
1. 每天早上 8:30 自动执行阶段 4 的那条命令（注意带 SKIP_IMA_SYNC=1）。
2. 每天完成后：把日报链接/文件发我 + 汇报 Top 10。
3. 如果当天更新数为 0，正常发一份「今天无更新」的说明，不要当成故障。

【长期约定】
1. 任何一次运行报 errCode=-2010（登录失效）：自动跑阶段 2 的扫码流程，
   把新二维码发我；我 12 小时内没扫就先跳过当天，第二天再提醒我。
2. 某些文章抓不到文字正文（图片型）是正常现象，保留标题+摘要+链接继续，
   不要反复重试。
3. 全程只用微信读书只读接口，不碰微信客户端，不做任何写操作。
4. 我读完日报后会把「复制全部批注」的内容粘贴给你，你把它整理成
   「文章 → 划线 → 我的批注」结构存进你的记忆，每周日给我一份阅读复盘。
```

## 第三部分：流水线规范（给执行者看的能力说明书）

一键入口：`bash <项目根>/scripts/run_daily.sh`（2026-10-28 起已跨平台适配：Linux 云主机自动用 python3 和 playwright 默认浏览器，无需改代码）。

| 步 | 动作 | 脚本 | 输出 | 成功判据 | 失败分支 |
|---|---|---|---|---|---|
| 0 | 登录态体检 | run_daily.sh 内置 | IN/OUT | IN → 继续 | OUT → 退出码 3，走扫码流程 |
| 1 | 扫码登录（首次/失效时） | weread_login.py | data/weread_profile | 状态文件 LOGIN_OK | 二维码发给用户等扫 |
| 2 | 抓全部公众号文章列表 | weread_fetch.py --days 1 | data/articles-*.json | 退出码 0 | errCode=-2010 → 回步骤 1 |
| 3 | 打分排序选 Top30 | wx_rank.py --days 1 --top 30 | data/ranked-*.json | top 数组生成 | 无更新出空日报，不算失败 |
| 4 | 概览/主题/推荐 | wx_insight.py | data/insights-*.json | 文件生成 | 非关键，不阻断 |
| 5 | 抓 Top25 正文（免跳转关键） | weread_content.py --top 25 | data/articles-full-*.json | 成功 ≥15 篇 | 空正文记入 unreadable，重试 ≤1 次 |
| 6 | 生成精读版日报 | wx_reader.py --top 25 | output/公众号日报-精读版-*.html | `<article id="art-` 计数 = 内嵌数 | — |

**退出码**：0 成功 / 2 抓取失败 / 3 登录失效。
**云端参数**：`SKIP_IMA_SYNC=1`（跳过本地划线同步服务，省 25 秒；ima 知识库是腾讯生态的可选环节，云端部署不迁移，批注归档由灵光自己承担）。

## 推荐引擎打分口径（个性化核心，可迭代）

```
总分 = 1.0×类型分 + 1.6×热度分 + 1.1×时效分 + 0.9×关键词分 + 学习分
热度分 = log10(阅读数+1) / 5        （10 万阅读 ≈ 1.0 满分）
时效分 = max(0, 1 - 发布小时数/168) （7 天内线性衰减）
```
（基准：`wx_rank.py` 顶部常量与第 105-129 行，调权重只改常量）

- 账号类型权重基线：AI 产品与工具实践 1.00 > 大厂官方技术号 0.95 > 创业与产业观察 0.90 > 媒体资讯 0.68 > …… > 个人 IP 0.30
- 关键词：加分词（agent / skill / mcp / 工作流 / 实测 / 教程 / 架构……）；减分词（抽奖 / 优惠 / 招聘 / 直播预告……）
- 去重：同号 + 标题前 12 字相同只留最高分
- 反馈学习（保留）：日报页 👍/👎 导出 feedback.json（单篇 +0.6/-1.2，账号级 ±0.15/±0.3）；划线提炼 learned_kw.json（单词 0.5，上限 3 词）。文件缺失自动退化为无学习模式，不报错。

## 异常处理速查表

| 现象 | 判定 | 处理 |
|---|---|---|
| errCode=-2010 | 登录失效 | 重跑扫码流程，二维码发用户 |
| 某篇正文为空 | 分享模板或纯 SVG | 记入 unreadable 保留链接，继续 |
| 某号抓取超时 | 个别号问题 | 跳过记录，不阻断 |
| 更新数为 0 | 当天没更新 | 正常发「无更新」说明 |
| 云主机重启后 profile 丢失 | 持久化缺失 | 立刻告知用户，讨论持久卷方案 |
| 重复触发 | 调度层问题 | 加执行锁（lock 文件存在即退出） |

## 第四部分：风险与不确定点（部署前必读，均无实锤、只能实测）

1. **数据中心 IP 风控**：云主机 IP 属数据中心段，用微信扫码登录微信读书**可能**触发风控（相比家庭 IP 风险更高）。无法预先验证。若登录后接口调用受限，此路不通，退回本地方案。
2. **登录态持久性**：灵光云主机是否长期保留文件，公开报道（2026-10-27 发布会，科技日报/北京商报等四源）只说「依托独立云主机支持任务持续运行」，没说文件系统持久化细节。阶段 0 必须实测：部署后隔天重启再验证登录态仍在。若每次任务都是全新环境，需把 `data/` 目录放进持久卷。
3. **日报交付形态**：云主机上的 HTML 文件如何送达用户（发文件？托管链接？），取决于灵光的文件交付能力，Prompt 里让灵光自选可行方式并如实报告。
4. **UA 指纹一致性**：脚本用固定 UA（Windows Chrome 149）从 Linux 发请求，理论上无影响（浏览器 UA 本就千差万别），但不排除微信读书端做一致性校验。实测为准。

**已验证可行的部分**：2026-10-28 已完成跨平台适配并冒烟通过——`find_exe()` 在无候选路径时回退 playwright 默认浏览器（本机候选命中行为不变）；`run_daily.sh` 的 Python 解释器自动探测（本机专用路径 > python3 > python）；`SKIP_IMA_SYNC=1` 开关。本机回归测试：抓取链路 7 秒通过。
